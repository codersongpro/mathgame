# Bubble Semble 설계 명세

- 작성일: 2026-09-22
- 문서 상태: 사용자 승인 완료
- 대상: 초등 1~6학년, 교사, 최대 10명의 학생
- 플랫폼: 태블릿·PC 웹 브라우저
- GitHub 저장소: `https://github.com/codersongpro/mathgame`
- 주 배포 환경: Vercel
- 실시간 게임 서버: Cloudflare Workers와 방 단위 Durable Objects

## 1. 제품 목표

Bubble Semble은 학생들이 같은 온라인 스테이지에서 실시간으로 움직이고, 몬스터를 거품에 가두고, 수학 문제를 해결해 스테이지와 보스를 공략하는 협동형 교육 게임이다.

제품의 핵심 목표는 다음과 같다.

1. 초등학생이 키보드 없이 태블릿 터치만으로 플레이할 수 있다.
2. 1명부터 10명까지 같은 게임 세계에서 실시간으로 협동한다.
3. 계산뿐 아니라 초등 수학의 여러 개념을 게임 행동과 연결한다.
4. 공개 서열보다 학생 개인의 성장 기록을 중심으로 보여준다.
5. 보스전은 팀 협동 타임어택으로 기록한다.
6. 이메일·전화번호·실명 없이 학교 수업에서 사용할 수 있다.

## 2. 확정된 제품 원칙

- 기존 상용 거품 액션 게임의 캐릭터·맵·로고·음악을 복제하지 않는다.
- 거품 포획과 협동 액션이라는 일반적 게임 규칙만 활용한다.
- 시각 방향은 밝고 귀여운 레트로 픽셀 아케이드 스타일이다.
- 한 세트는 일반 스테이지 3개와 보스 스테이지 1개로 구성한다.
- 한 세트의 목표 플레이 시간은 10분이다.
- 보스 클리어 후 다음 난이도의 세트로 진행한다.
- 참여 인원이 늘어나면 맵, 몬스터, 문제, 보스 난이도가 함께 확장된다.
- 모든 플레이어가 같은 게임 세계를 공유하되 각 기기는 자기 캐릭터를 따라가는 개인 카메라를 사용한다.
- 학생 간 자유 채팅과 개인 메시지는 제공하지 않는다.

## 3. 사용자 역할

### 3.1 교사

- 학급을 생성하고 학급 코드를 관리한다.
- 게임 방을 만들고 학년, 영역, 난이도, 제한 시간을 설정한다.
- 구구단은 1단부터 19단까지 단일 또는 복수로 선택한다.
- 참여 학생을 확인하고 게임을 시작·일시정지·종료한다.
- 학생별 성장 기록과 학급 요약을 확인한다.
- 분실한 학생 PIN을 초기화한다.

### 3.2 학생

- 학급 코드, 별명, 개인 PIN으로 접속한다.
- 교사가 만든 방 코드로 게임에 참여한다.
- 자신의 성장 기록과 배지를 확인한다.
- 다른 학생의 상세 성적이나 전체 공개 순위는 볼 수 없다.

## 4. 접속과 계정

### 4.1 학생 로그인

학생 로그인 정보는 다음 세 가지다.

```text
학급 코드 + 학생 별명 + 개인 PIN
```

- 이메일, 전화번호, 사진, 실명은 요구하지 않는다.
- 시스템 내부에서는 무작위 학생 ID를 사용한다.
- 별명은 학급 안에서만 고유하다.
- 별명 길이는 2~12자로 제한하고 허용 문자와 금칙어를 검사한다.
- PIN은 4~8자리 숫자로 제한한다.
- 로그인 연속 실패에는 속도 제한과 임시 잠금을 적용한다.
- PIN은 복호화할 수 없는 Argon2id 해시로 저장한다.
- 별명과 학습 기록은 애플리케이션 계층에서 AES-256-GCM으로 암호화해 저장한다.
- 암호화 키는 데이터베이스와 분리된 비밀 저장소에서 관리한다.
- 모든 네트워크 통신은 HTTPS와 WSS를 사용한다.

### 4.2 방 코드

- 방 코드는 앞의 0을 포함할 수 있는 숫자 6자리 문자열이다.
- 한 방의 최대 인원은 학생 10명과 관전자 역할의 교사 1명이다.
- 방 코드는 게임 종료 30분 후 만료한다.
- 사용 중인 방 코드는 중복 발급하지 않는다.
- 학생은 자신이 속한 학급의 활성 방에만 참여할 수 있다.

## 5. 핵심 게임 흐름

```text
로그인
  ↓
학급·방 참여
  ↓
캐릭터 선택과 준비
  ↓
일반 스테이지 1: 기본 전투·개인 문제
  ↓
일반 스테이지 2: 구역 분담·개념 문제
  ↓
일반 스테이지 3: 강화 전투·팀 수학 관문
  ↓
보스전: 협동 문제·팀 타임어택
  ↓
성장 결과와 다음 난이도 세트
```

### 5.1 시간 배분

| 구간 | 목표 시간 |
|---|---:|
| 일반 스테이지 1 | 2분 |
| 일반 스테이지 2 | 2분 |
| 일반 스테이지 3 | 2분 |
| 보스전 | 4분 |

- 로그인, 캐릭터 선택, 결과 확인 시간은 10분에 포함하지 않는다.
- 제한 시간을 초과해도 즉시 게임을 종료하지 않는다.
- 초과 시간은 성장 평가와 타임어택 보정에 반영한다.
- 교사는 세트 종료 후 다음 세트를 시작하지 않고 수업을 마칠 수 있다.

## 6. 플레이어 행동과 터치 조작

### 6.1 기본 행동

- 왼쪽·오른쪽 이동
- 점프
- 아래 발판 통과
- 거품 발사
- 거품 터뜨리기 또는 짧은 팝 대시
- 상호작용·정답 선택
- 팀 필살기
- 쓰러진 친구 구출

### 6.2 태블릿 UI

- 가로 화면을 기본으로 한다.
- 왼쪽에는 이동 버튼, 오른쪽에는 행동 버튼을 배치한다.
- 터치 목표 크기는 최소 64 CSS 픽셀로 한다.
- 점프, 거품, 팝 대시는 색상과 모양을 모두 다르게 한다.
- 색상만으로 상태를 전달하지 않고 아이콘·외곽선·진동을 함께 사용한다.
- 화면 회전이나 일시적인 브라우저 UI 변화에도 게임판 비율을 유지한다.
- 키보드는 선택적 보조 입력이며 필수 입력이 아니다.

## 7. 수학과 전투의 연결

### 7.1 혼합형 문제 구조

- 일반 전투에서는 학생마다 짧은 개인 문제가 제공된다.
- 정답을 맞히면 거품 공격, 보호막, 이동 보조, 팀 게이지가 강화된다.
- 오답에는 즉시 탈락 대신 부분 힌트와 한 번의 빠른 재도전을 제공한다.
- 스테이지 중간의 수학 관문에서는 팀원이 역할을 나누어 문제를 해결한다.
- 보스전에서는 팀 문제를 해결해 방어막을 제거하고 공격 기회를 연다.

### 7.2 문제 표현

- 정답 거품 선택
- 수 크기순 배열
- 같은 값 연결
- 수직선 위치 선택
- 시계 바늘 조작
- 길이·넓이·분수 조각 비교
- 도형 회전과 분류
- 표·그래프 정보 찾기
- 여러 학생의 정답 조각 결합

### 7.3 개인화

- 같은 팀에서도 학생별 문제 난이도는 다를 수 있다.
- 다른 학생에게 개인 난이도와 오답 이력을 표시하지 않는다.
- 최근 정확도, 풀이 시간, 힌트 사용량을 이용해 다음 문제를 조절한다.
- 한 세트 안에서는 난이도를 한 단계 이상 급격히 변경하지 않는다.
- 개인화가 실패하거나 기록이 부족하면 교사가 선택한 기본 난이도를 사용한다.

## 8. 수학 콘텐츠 범위

| 학년군 | 주요 영역 |
|---|---|
| 1~2학년 | 수 감각, 덧셈·뺄셈, 기초 곱셈, 시각, 길이, 규칙, 기본 도형 |
| 3~4학년 | 곱셈·나눗셈, 분수·소수 기초, 각도, 평면도형, 측정, 표와 그래프 |
| 5~6학년 | 분수·소수 계산, 약수·배수, 비와 비율, 넓이·부피, 평균, 자료 해석 |

### 8.1 구구단

- 1단부터 19단까지 개별 선택한다.
- 여러 단을 동시에 선택할 수 있다.
- 순차, 무작위, 역산 유형을 지원한다.
- 오답이 잦은 단은 같은 세트 안에서 표현을 바꾸어 다시 출제한다.

### 8.2 문제 안전성

- 계산형 문제는 규칙 기반 생성기를 사용한다.
- 정답은 생성 시점과 제출 시점에 서버가 각각 검증한다.
- 도형·그래프형 문제는 검수된 템플릿과 파라미터만 사용한다.
- 동일 학생에게 같은 표현의 문제가 짧은 간격으로 반복되지 않도록 문제 ID를 기록한다.
- 문제 데이터에는 학년군, 영역, 기술, 난이도, 정답, 풀이 규칙, 힌트 단계, 검수 버전을 저장한다.

## 9. 멀티플레이 동작

### 9.1 공유되는 상태

- 맵과 발판
- 플레이어와 몬스터 위치
- 거품과 아이템
- 스테이지 목표
- 보스 체력과 공격 단계
- 팀 게이지와 남은 시간
- 팀 수학 관문 상태

### 9.2 개별 상태

- 카메라 위치
- 터치 버튼
- 개인 문제와 힌트
- 개인 성장 알림
- 네트워크 품질 표시

### 9.3 서버 권한

- 클라이언트는 이동 방향과 행동 요청만 보낸다.
- 서버가 몬스터, 거품 포획, 공격, 점수, 정답, 보스 피해를 최종 판정한다.
- 클라이언트가 보낸 위치, 점수, 정답 결과를 그대로 신뢰하지 않는다.
- 입력 메시지는 스키마, 빈도, 범위를 검증한다.
- 비정상적인 입력 빈도에는 무시, 경고 로그, 연결 제한을 순서대로 적용한다.

### 9.4 동기화 기준

- 서버 게임 루프는 초당 20회 실행한다.
- 상태 스냅샷은 초당 10회 전송한다.
- 로컬 플레이어는 입력 예측을 사용한다.
- 다른 플레이어와 몬스터는 보간해 표시한다.
- 서버 판정과 차이가 날 때는 짧은 시간에 걸쳐 위치를 보정한다.
- 연결이 60초 안에 복구되면 같은 캐릭터로 재접속한다.
- 60초가 지나면 해당 캐릭터를 안전 구역으로 이동시키고 난이도를 다시 계산한다.

## 10. 인원별 맵과 난이도 확장

| 인원 | 맵 규모 | 동시 전투 구역 | 동시 문제 구역 |
|---:|---|---:|---:|
| 1~2명 | 소형 | 1 | 1 |
| 3~5명 | 중형 | 2 | 1 |
| 6~8명 | 대형 | 2 | 2 |
| 9~10명 | 특대형 | 3 | 3 |

- 맵은 인원 구간별로 검수된 레이아웃을 선택한다.
- 진행 중 인원이 변해도 현재 맵 구조를 갑자기 교체하지 않는다.
- 중도 이탈 시 몬스터 생성 수, 남은 문제 수, 보스 체력만 재조정한다.
- 넓은 맵에서는 구역별 임무를 수행하고 포털로 합류한다.
- 보스전에서는 모든 학생이 하나의 경기장에 모인다.
- 멀리 있는 팀원은 화면 가장자리 방향 표시와 미니맵으로 안내한다.

### 10.1 난이도 보정 규칙

- 기본 몬스터 수는 스테이지 템플릿에 정의한다.
- 추가 플레이어 2명마다 동시 몬스터 한도를 1마리씩 늘린다.
- 동시 몬스터 한도는 태블릿 성능을 위해 구역당 8마리를 넘지 않는다.
- 팀 문제 조각 수는 참여 인원의 60%를 올림한 값으로 하되 2~6개로 제한한다.
- 보스 최대 체력은 기본 체력에 `1 + 0.55 × (인원 - 1)`을 곱한다.
- 보스 공격 빈도는 6명 이상부터 최대 20%까지만 증가한다.
- 보스 타임어택에는 실제 시간과 인원 보정 시간을 함께 기록한다.

## 11. 스테이지와 보스

### 11.1 일반 스테이지

1. 스테이지 1은 이동, 거품 포획, 개인 문제를 익히게 한다.
2. 스테이지 2는 두 개 이상의 구역과 포털 합류를 사용한다.
3. 스테이지 3은 강화 몬스터와 팀 수학 관문을 사용한다.

### 11.2 첫 번째 보스

- 이름: 혼돈의 큐브왕
- 외형: 숫자 블록, 분수 타일, 시계 톱니, 도형 판으로 구성된 독창적인 큐브 생물
- 1단계: 숫자 블록 회피와 개인 문제
- 2단계: 여러 구역의 정답 조각 수집
- 3단계: 팀 문제를 해결해 방어막 파괴
- 마무리: 전원이 안전한 거품 연쇄 공격에 참여
- 폭력적 연출 대신 큐브가 빛나는 조각으로 분해되어 정화되는 표현을 사용한다.

## 12. 성장 기록과 타임어택

### 12.1 개인 성장 기록

- 학년·영역·기술별 숙련도
- 최근 정답률과 풀이 시간
- 최고 연속 정답
- 힌트 사용 변화
- 완료한 세트와 도달 난이도
- 친구 구출과 문제 지원 횟수
- 이전 기록 대비 향상 항목

### 12.2 노출 원칙

- 학생 화면은 자신의 성장 변화가 중심이다.
- 전체 학생 공개 순위표를 제공하지 않는다.
- 교사는 담당 학급의 학생 기록만 확인한다.
- 성장 배지는 실력뿐 아니라 꾸준함과 협동 행동에도 부여한다.

### 12.3 보스 협동 타임어택

- 참여 인원

## 13. 그래픽과 에셋

### 13.1 시각 방향

- 레트로 픽셀 아케이드
- 굵은 짙은 남색 외곽선
- 높은 명도 대비
- 어린이에게 친근한 마법 탐험 분위기
- 32×32 타일 기준
- 플레이어와 일반 몬스터는 48×48 프레임
- 보스는 128×96 프레임
- 안티앨리어싱과 흐림을 사용하지 않는다.

### 13.2 캐릭터

- 최대 10명이 동시에 구별되도록 실루엣과 대표색을 다르게 한다.
- 대표 캐릭터 루미의 승인된 시드 프레임을 먼저 제작한다.
- 대기, 달리기, 점프, 거품 발사, 팝 대시, 피격, 구출, 승리 애니메이션을 제공한다.
- 왼쪽 방향은 오른쪽 스프라이트를 게임에서 수평 반전한다.

### 13.3 제작 파이프라인

1. 승인된 시드 프레임을 만든다.
2. 같은 캐릭터의 애니메이션을 한 개의 전체 스트립으로 생성한다.
3. 공통 배율을 사용해 고정 크기 프레임으로 정규화한다.
4. 모든 프레임을 하단 중앙 앵커로 정렬한다.
5. 미리보기 시트와 실제 게임 크기에서 검수한다.
6. 승인된 에셋만 게임 목록에 등록한다.

에셋 생성 프롬프트의 기준 문서는 `outputs/bubble-semble-graphics-prompts.md`다.

## 14. 시스템 구조

```text
Vercel 웹 앱
  ├─ Next.js 기반 로비·교사 화면·성장 기록
  ├─ Phaser 2D 게임 화면
  ├─ 반응형 DOM HUD와 터치 입력
  └─ Vercel Functions 기반 일반 API
              │
              ├──── HTTPS ──── PostgreSQL
              │                 ├─ 학급·학생·교사 권한
              │                 ├─ 문제 템플릿·성장 기록
              │                 └─ 타임어택·감사 로그
              │
              └──── WSS ─────── Cloudflare 실시간 서버
                                ├─ 방 코드별 Durable Object 1개
                                ├─ 최대 10명 연결·재접속
                                ├─ 게임 루프·몬스터·보스 판정
                                ├─ 문제·정답·난이도 판정
                                └─ 검증된 결과만 API로 저장
```

### 14.1 클라이언트

- Next.js, TypeScript, Phaser 3를 사용한다.
- 게임판은 Canvas/WebGL로 렌더링한다.
- 로그인, 로비, 퀴즈 카드, 성장 기록은 접근성이 좋은 DOM UI로 구현한다.
- 게임 상태와 UI 상태를 분리한다.
- 서버가 보낸 검증된 공개 상태만 렌더링한다.

### 14.2 Vercel 웹·API

- GitHub 저장소와 Vercel 프로젝트를 연결한다.
- 웹 게임, 로비, 교사 화면, 성장 기록 화면을 Vercel에 배포한다.
- 로그인, 학급, 문제 설정, 성장 기록 조회·저장은 Vercel Functions로 처리한다.
- 실시간 게임 루프와 장시간 WebSocket 연결은 Vercel Functions에 넣지 않는다.
- Vercel API는 Cloudflare 실시간 서버가 제출한 게임 결과의 서명과 멱등 키를 검증한다.

### 14.3 실시간 서버

- TypeScript 기반 Cloudflare Worker와 Durable Object를 사용한다.
- 방 코드 하나는 Durable Object 하나에 대응한다.
- 방 하나는 독립된 게임 상태, WebSocket 연결, 게임 루프를 가진다.
- 방 간 상태를 공유하지 않는다.
- 메시지 형식은 버전이 있는 명시적 스키마로 관리한다.
- 동일 입력을 재전송해도 점수나 보상이 중복되지 않도록 이벤트 ID를 사용한다.
- Durable Object는 한 방의 연결을 단일 지점에서 조정해 순서가 있는 권한형 판정을 수행한다.
- 스테이지 체크포인트와 재접속용 최소 상태는 Durable Object 저장소에 기록한다.
- 게임 결과는 서버 서명과 멱등 키를 포함해 Vercel API로 전송한다.

### 14.4 데이터베이스

- PostgreSQL을 사용한다.
- SQL 파일은 `database/migrations`에만 둔다.
- 마이그레이션 파일은 `001_설명.sql` 형식으로 순서를 붙인다.
- 학습 기록 원본 이벤트와 집계 결과를 분리한다.
- 삭제·정정 요청을 추적할 수 있도록 관리자 감사 로그를 남긴다.

### 14.5 저장소 구조

```text
mathgame/
  apps/
    web/                 # Vercel: Next.js, Phaser, 로비·교사 UI
    realtime/            # Cloudflare Worker와 Durable Objects
  packages/

    game-core/           # 문제·난이도·점수의 순수 규칙
  database/
    migrations/          # 001_설명.sql 형식의 SQL 파일
  assets/

    worlds/
    effects/
    ui/
  docs/
    superpowers/

```

웹 앱과 실시간 서버는 같은 저장소의 공통 타입과 검증 스키마를 사용하되 각각 독립적으로 빌드·배포한다.

### 14.6 Git과 배포 흐름

- `main`을 Vercel 프로덕션 브랜치로 사용한다.
- 기능 브랜치와 Pull Request는 Vercel Preview Deployment를 생성한다.
- `apps/web`의 관련 테스트와 빌드가 성공한 경우에만 Vercel 배포를 허용한다.
- `apps/realtime`의 단위·통합 테스트가 성공한 경우에만 Cloudflare Preview 환경에 배포한다.
- 미리보기에서 대표 태블릿 경로와 10개 자동 클라이언트 연결을 검증한 뒤 `main`에 병합한다.
- Vercel 및 Cloudflare 토큰, 데이터베이스 URL, 암호화 키는 저장소에 커밋하지 않는다.
- 운영 배포 실패 시 웹 앱과 실시간 서버를 각각 직전 검증 버전으로 되돌릴 수 있어야 한다.

## 16. 오류와 장애 대응

### 16.1 네트워크

- 연결이 불안정하면 화면에 연결 품질을 표시한다.
- 입력 전송이 잠시 끊기면 캐릭터를 안전하게 정지시킨다.
- 재접속 중에도 다른 학생의 게임은 계속된다.
- 서버와 다시 연결되면 전체 상태 스냅샷을 받아 복구한다.

### 16.2 서버

- 방 서버 오류 시 마지막 체크포인트 상태를 저장한다.
- 복구 가능한 경우 같은 방 코드로 재개한다.
- 복구할 수 없으면 해당 세트를 무효 처리하고 성장 기록에 실패로 남기지 않는다.
- 중복 정답 제출과 중복 보상은 이벤트 ID로 차단한다.

### 16.3 문제

- 문제 생성 또는 검증에 실패하면 해당 문제를 폐기하고 같은 기술의 검수된 예비 문제를 제공한다.
- 정답이 여러 개로 해석될 수 있는 문제는 출제하지 않는다.
- 게임 진행 중 문제 오류가 발견되면 해당 시도의 성장도 반영을 취소하고 관리자 로그에 기록한다.

### 16.4 데이터

- 기록 저장 실패 시 서버가 암호화된 재시도 큐에 보관한다.
- 같은 기록을 다시 저장해도 한 번만 반영되도록 멱등 키를 사용한다.
- 저장 완료 전 결과 화면에 영구 저장 완료로 표시하지 않는다.

## 17. 보안과 개인정보

- 최소 정보만 수집한다.
- 학생 실명 입력을 유도하지 않는다.
- 역할 기반 접근 제어를 사용한다.
- 학생은 자신의 기록만, 교사는 담당 학급 기록만 접근한다.
- 방 참여, 문제 제출, 교사 기능에 서버 권한 검사를 적용한다.
- 입력값 길이, 문자, 범위, 메시지 빈도를 검증한다.
- 비밀키와 데이터베이스 자격 증명을 코드나 클라이언트 번들에 포함하지 않는다.
- 운영 로그에 PIN, 토큰, 문제 응답 전문, 복호화된 별명을 남기지 않는다.
- 성장 기록과 감사 로그의 보존 기간을 분리한다.
- 데이터 내보내기와 삭제는 교사 권한과 감사 기록을 거쳐 수행한다.

## 18. 접근성과 교육적 안전

- 정답·오답을 색상만으로 구분하지 않는다.
- 큰 글자와 충분한 대비를 사용한다.
- 효과음, 배경음, 화면 흔들림을 각각 끌 수 있다.
- 시간 압박이 어려운 학생을 위해 연습 모드를 제공한다.
- 오답을 비난하거나 공개하지 않는다.
- 게임 기여도는 전투뿐 아니라 문제 해결, 구출, 지원도 인정한다.
- 빠른 학생이 모든 문제를 독점하지 못하도록 역할과 문제를 분배한다.

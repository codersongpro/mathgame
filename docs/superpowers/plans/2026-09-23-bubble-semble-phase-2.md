# Bubble Semble 페이즈 2 구현 계획

## 목표와 범위

페이즈 1의 10인 공유 방과 태블릿 조작을 유지하면서, 일반 스테이지 1개에 필요한 거품 전투·개인 계산 문제·협동 목표를 순서대로 추가한다. 서버가 행동과 정답을 판정하고 Phaser는 결과만 그린다. 이번 작업에서는 첫 묶음인 **거품 발사 → 몬스터 포획 → 거품 터뜨리기**를 완성한다.

현재 운영 중인 `main`은 이 계획의 검증이 끝날 때까지 그대로 두고, `codex/bubble-semble-phase-2` 브랜치에서 작업한다.

|---|---|---|---|

## 첫 묶음의 설계

- 터치 버튼 두 개를 추가한다: `거품 발사`, `팡!`. 이동·점프와 동시에 누를 수 있도록 행동을 별도 메시지로 보낸다.
- 행동 메시지에는 종류·순서·방향만 담는다. 위치, 몬스터 ID, 포획 결과는 클라이언트가 결정하지 않는다.
- 서버는 20Hz 루프에서 거품 이동과 몬스터 충돌을 판정한다. 기존 위치 스냅샷은 유지하고, 10Hz의 별도 전투 메시지에 거품·몬스터·팀 포획 수를 담는다. 이전 웹 버전은 새 메시지를 무시해 이동을 계속할 수 있다.
- 새 웹 버전은 첫 전투 메시지를 받기 전에는 행동 버튼을 비활성화해, 웹이 먼저 배포되어도 구버전 서버에 행동 요청을 보내지 않는다.
- 몬스터는 인원에 따라 정해진 상한만큼 등장한다. 추가 플레이어 2명당 한 마리를 늘리고, 첫 묶음에서는 한 구역에 최대 8마리로 제한한다.
- 몬스터를 가둔 거품을 학생이 가까이서 `팡!` 하면 팀 포획 수가 오른다. 제한 시간 안에 터뜨리지 못하면 몬스터가 풀려난다.
- 거품과 몬스터는 임시 픽셀 형태로 그린다. 완성형 에셋은 페이즈 6에서 교체한다.

## 안전·검증 경계

- 기존 방 코드, 재접속, 10인 정원, 맵 고정 규칙을 유지한다.
- 발사 연타는 서버 쿨다운과 기존 입력 빈도 제한으로 제어한다.
- 먼저 관련 규칙·통합·터치 테스트를 통과시키고, 타입 검사와 빌드를 확인한다.
- 실제 브라우저에서는 태블릿 가로 화면에서 발사, 포획, 터뜨리기를 한 경로로 확인한다.
- `main` 병합과 운영 배포는 별도 단계다. 이번 묶음의 검증 결과를 사용자에게 먼저 보여준다.

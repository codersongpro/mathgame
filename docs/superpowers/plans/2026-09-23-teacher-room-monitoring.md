# Bubble Semble 교사 방 자동 발급·모니터링 구현 계획

## 현재 상태와 목표

- 현재 로비는 학생이 6자리 숫자를 직접 입력하며, 입력된 번호에 해당하는 게임방이 자동으로 열립니다. 교사 권한, 자동 발급, 교사 화면은 없습니다.
- 이번 변경의 목표는 교사가 접근키로 방을 열면 서버가 중복 없는 6자리 숫자를 발급하고, 학생은 번호만 입력하며, 교사는 학생 접속·팀 포획·이후 문제 진행을 별도 화면에서 확인하는 것입니다.
- 작업은 `codex/bubble-semble-phase-2` 브랜치에서 진행합니다. `main`과 운영 Vercel·Cloudflare에는 검증 전 반영하지 않습니다.

## 결정과 경계

| 항목 | 결정 | 이유 |
|---|---|---|
| 교사 방 생성 | 교사 접근키를 입력하고 `방 열기`를 누르면 발급 | 새로고침만으로 방이 계속 생기는 사고 방지 |
| 생성 권한 | Cloudflare 비밀 설정 `TEACHER_CREATE_KEY`와 서버에서 비교 | 학생이나 외부인이 임의로 방을 대량 생성하는 것을 방지 |
| 방 번호 | 암호학적 난수로 숫자 6자리 생성, 앞의 0 유지 | 태블릿에서 입력하기 쉽고 예측 가능성을 낮춤 |
| 중복 방지 | 코드별 기존 `GameRoom` Durable Object의 최초 생성 저장을 원자적으로 확인, 충돌 시 재시도 | 별도 DB·새 Durable Object 클래스를 늘리지 않음 |
| 교사 모니터 권한 | 방마다 별도 무작위 토큰 발급, 서버에는 해시만 저장 | 학생용 6자리 번호만으로 교사 화면에 들어갈 수 없음 |
| 브라우저의 교사 토큰 | Vercel의 `HttpOnly`·`Secure`·`SameSite` 쿠키에 방별 저장 | 주소·화면·브라우저 스크립트에 비밀키 노출 방지 |
| 교사 현황 | Vercel 서버가 토큰으로 Worker에 조회하고 화면은 2초 간격 갱신 | 교사 비밀을 클라이언트 WebSocket URL에 넣지 않음 |
| 방 수명 | 최초 발급 뒤 4시간 입장 허용, 만료된 코드는 재발급하지 않음 | 오래된 교사 권한과 방 재사용을 제한 |
| 학생 정보 | 현재 단계에서는 기존 임시 별명·접속 상태·팀 포획만 표시 | 실명·개별 성적의 신규 저장을 시작하지 않음 |

교사 접근키는 코드나 문서에 값을 넣지 않고 Cloudflare 환경별 Secret으로 등록합니다. Preview와 Production에 서로 다른 값을 사용합니다. 학생 별명은 현재의 임시 별명 정책을 유지하며, 학생 문제 기록·장기 성장 기록은 이번 교사 방 기능에 포함하지 않습니다.

## 실행 단계와 검증

| 순서 | 무엇을 할지 | 관련 파일 | 왜·완료 기준 | 검증 |
|---|---|---|---|---|
| 1 | 방 최초 생성·권한 규칙 추가 | `apps/realtime/src/GameRoom.ts`, `apps/realtime/src/index.ts`, 공용 스키마 | 접근키가 맞을 때만 6자리 방 발급; 충돌하면 새 번호; 발급 전 임의 번호 입장 거부; 교사 토큰 해시만 저장 | Worker 및 Durable Object 테스트: 인증 실패, 중복 충돌, 앞자리 0, 미생성 방 거부, 토큰 실패 |
| 2 | 교사용 서버 API 추가 | `apps/web/src/app/api/teacher/...` | Vercel이 Worker를 호출해 토큰을 방별 HttpOnly 쿠키에 저장; 학생에게 토큰 반환 금지 | API 테스트·응답 헤더 확인: 쿠키 보안 속성, 캐시 금지, 토큰 무노출 |
| 3 | 교사 화면 추가 | `apps/web/src/app/teacher/...`, `apps/web/src/components`, 로비 링크·CSS | 교사는 방을 열고 번호를 학생에게 안내; 접속자 수·학생 별명/연결 상태·팀 포획을 2초 이내에 확인 | 가로/세로 태블릿 브라우저: 생성→학생 2명 입장→교사 현황 갱신, 비밀키 없는 접근 차단 |
| 4 | 개인 수학 문제 다음 묶음 | `packages/game-core`, `apps/realtime`, 게임 문제 카드, 교사 현황 | 학생마다 다른 문제를 받고 서버가 정답을 판정; 교사 현황에 익명/별명 기준 진도 표시 | 문제 생성·정답/오답·재접속·권한 테스트 후 별도 사용자 확인 |

1~3을 한 기능으로 완성·검증하고 사용자에게 화면을 보여준 뒤 4로 넘어갑니다. 4에서 학생별 학습 기록을 새로 저장할 때에는 별도 암호화 키와 보존 정책을 먼저 정해, 민감한 교육 정보가 평문으로 남지 않게 합니다.

## 배포와 되돌리기

- Worker와 Vercel은 서로 맞는 버전이 필요합니다. Preview에서 먼저 둘 다 배포해 `방 열기 → 코드 공유 → 학생 입장 → 교사 현황`을 검증합니다.
- Cloudflare Preview·Production에 `TEACHER_CREATE_KEY`를 각각 Secret으로 설정해야 방 생성이 동작합니다. 미설정 시 생성은 명시적으로 실패해야 하며 임의 기본값으로 열리지 않습니다.
- 운영 배포는 사용자가 직접 합니다. 이 계획만으로 `main` 병합·GitHub push·운영 배포를 수행하지 않습니다.
- 현재 수동으로 입력해 열던 임의 숫자 방은 새 버전에서 더 이상 열리지 않습니다. 운영 전 교사에게 새 흐름을 안내해야 합니다.

## 남은 제품 결정

- 이번 단계의 교사 화면은 접속·팀 활동 모니터입니다. 학생별 정답률·성장 기록은 개인 문제와 암호화 저장 정책을 구현한 뒤 추가합니다.
- 로그인 없이 공유 접근키를 사용하는 교사 기능은 학교 계정과 연결되지 않습니다. 장기 기록과 여러 교사의 권한 분리가 필요해질 때 계정 인증으로 확장합니다.

## 2026-09-28 구현·검증 기록

- 1~3단계의 Worker 방 발급·미발급 방 차단·교사 토큰, Vercel 서버 API·보안 쿠키, 교사 화면을 로컬 작업 브랜치에 구현했습니다.
- Worker 실제 Durable Object 통합 테스트, 웹 관련 테스트, 두 앱의 타입 검사와 빌드는 통과했습니다.
- 로컬 Worker 설정 파일 경로를 쓰기 가능한 임시 위치로 분리한 뒤, 실제 브라우저에서 교사 방 발급→학생 2명 입장→현황 갱신과 새로고침 복구를 확인했습니다. 실제 Preview 환경은 아직 검증하지 못했습니다.
- Preview·Production 배포, `main` 병합, 실제 Cloudflare Secret 등록은 하지 않았습니다. 4단계 개인 수학 문제도 아직 시작하지 않았습니다.

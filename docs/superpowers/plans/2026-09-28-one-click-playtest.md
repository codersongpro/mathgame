# Bubble Semble: 교사 인증 원클릭 플레이 테스트

## 짧은 요약

교사가 기존 접속키로 인증한 뒤 `시험 플레이 시작`을 누르면 실제 실시간 방을 자동 발급하고 교사를 테스트 학생으로 바로 입장시킨다. 방 번호는 게임 규칙상 내부에서 계속 사용하지만 직접 입력하지 않는다.

## 전제와 보안 경계

- Vercel에 배포된 사이트에서도 사용한다. 방 생성 권한은 기존 교사 접속키 검증을 그대로 사용한다.
- 접속키 원문은 브라우저 저장소·URL·테스트 링크에 남기지 않는다. 새 인증 우회 API를 만들지 않는다.
- `mode=test`는 화면 표시와 공유 링크 버튼만 켠다. 이 매개변수에 권한은 없다.
- 테스트 방은 일반 방과 같은 게임 서버·점수·스테이지 규칙을 쓴다. 기존 4시간 만료와 최대 10인 제한도 동일하다.
- 테스트 링크에 포함되는 6자리 방 코드는 학생 입장용 공개 코드이며, 교사 토큰은 포함하지 않는다.
- 교사가 다른 기기에서 같은 테스트 링크를 열면 협동 플레이를 확인할 수 있다. 별명은 링크를 복사할 때 새로 붙인다.

## 실행 단계와 완료 기준

1. **교사 버튼**: 기존 방 생성 폼에 `시험 플레이 시작` 버튼을 추가하고 같은 인증 API를 호출한다. → 접속키가 없거나 틀리면 게임으로 이동하지 않는다.
2. **자동 입장**: 성공 응답의 방 코드로 `/play`에 이동하며 테스트 별명을 자동 설정한다. → 방 코드·별명 수동 입력 없이 실제 WebSocket 게임이 시작된다.
3. **테스트 도구**: 게임 화면에 테스트 표시, 친구 초대 링크 복사, 교사 모니터 이동을 보여준다. → URL과 클립보드에 비밀키·교사 토큰이 없다.
4. **검증**: 교사 버튼, 일반 방 개설, 자동 이동, 공유 링크, 기존 API 인증 테스트와 타입 검사·빌드를 확인한다.

## 제외

- 자동 조종 봇, 무인 10인 부하 테스트, 점수 조작, 인증 없는 공개 관리자 모드, 운영 데이터 장기 저장.

## 검증 결과

- 웹 패키지 테스트 34개와 프로덕션 빌드 통과.
- 일반 방 생성, 원클릭 테스트 이동, 잘못된 교사 키·방 번호 차단, 친구 링크의 비밀정보 배제를 확인.
- 이 작업 환경에는 Playwright 브라우저 실행 파일과 로컬 교사 키가 없어 실제 브라우저 수동 플레이는 수행하지 않음.
- 운영 `main` 및 Vercel·Cloudflare 배포는 이번 구현 중 변경하지 않음.

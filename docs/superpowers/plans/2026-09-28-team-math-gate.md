# Bubble Semble 페이즈 3-2: 팀 수학 관문 구현 계획

## 짧은 요약

3단계의 시간 또는 점수가 목표 절반에 이르면 팀 수학 관문을 엽니다. 여러 학생이 각자 수학 문제 조각을 풀어야 관문이 해제되고, 관문을 해제해야 3단계를 클리어할 수 있습니다.

## 결정과 범위

- 필요한 조각 수는 참가 인원의 60%를 올림한 값이며 최소 2개, 최대 6개입니다. 2명 이상이면 가능한 한 서로 다른 학생이 한 조각씩 풉니다. 혼자 남으면 같은 학생이 두 번째 조각을 풀 수 있어 진행이 막히지 않습니다.
- 관문 문제는 기존 20 이내 덧셈·뺄셈 생성기를 사용하되 학생마다 다른 식을 보냅니다. 답과 힌트는 개인 연결에만 보내고, 팀 화면에는 완료한 조각 수만 공유합니다.
- 문제 출제·정답·점수·참여자 구분은 서버에서 판정합니다. 클라이언트는 문제 ID와 선택지만 전송합니다.
- 중도 이탈로 인원이 줄면 필요한 조각 수를 현재 인원에 맞춰 낮춥니다. 이미 완료한 조각은 유지합니다.
- 현재 방의 팀 진행도만 체크포인트에 저장하고 학생별 오답·관문 문제·개인 기여 목록은 영구 저장하지 않습니다. 서버가 재시작하면 남은 조각은 새 문제로 다시 배정합니다.
- 보스전, 전 학년 문제, 영구 성장 기록은 이번 묶음에 포함하지 않습니다.

## 무엇을 할지 → 왜 → 어떻게 확인할지

| 단계 | 구현 | 이유 | 완료 기준 |
|---|---|---|---|
| 1. 관문 규칙·프로토콜 | 조각 수, 활성 조건, 개인 문제·답 메시지 | 10인 규모와 위조 답변을 안전하게 처리 | 1·2·10인 조각 수, 목표 절반, 메시지 검증 테스트 |
| 2. 실시간 서버 | 3단계 중간에 관문을 열고 여러 학생의 정답을 집계 | 한 명의 연타로 팀 관문을 끝내지 못하게 함 | 2인 방에서 각자 한 문제를 풀어야 클리어, 중복·위조·재접속 검증 |
| 3. 학생 화면 | 개인 문제 카드와 팀 조각 진행도 | 키보드 없이 협동 상황을 알게 함 | 터치 선택·오답 힌트·완료 안내 UI 테스트, 타입 검사·빌드 |

## 배포 경계

기능은 작업 브랜치에만 저장합니다. 실제 2인 태블릿 플레이 검증, `main` 병합과 운영 배포는 별도 단계입니다.

## 구현·검증 결과 (2026-09-28)

- 3단계 시간 또는 점수가 절반에 도달하면 개인별 관문 문제를 발급하고, 팀 조각을 모두 풀기 전에는 스테이지를 클리어하지 않게 했습니다.
- 2인 방에서 각자 한 조각을 풀어야 완료되고, 한 사람의 중복 제출과 학생 ID 위조는 거절했습니다. 1인 방에서는 순서대로 두 조각을 풀 수 있습니다.
- 교사에게는 조각 진행도만 보여주고 개인 관문 문제·정답은 전송하지 않습니다.
- 게임 규칙 34개, 공용 형식 13개, 실시간 서버 36개, 웹 38개 테스트가 통과했습니다. 타입 검사와 웹 빌드·Worker 드라이런도 통과했습니다.
- 실제 태블릿에서 동시 조작과 카드 배치는 아직 수동 확인하지 않았습니다. 다음 묶음은 보스전입니다.

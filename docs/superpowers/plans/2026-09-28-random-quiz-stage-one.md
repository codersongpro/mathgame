# Bubble Semble: 방별 무작위 문제와 일반 스테이지 1 시작

## 짧은 요약

새 교사 방마다 문제 출제 순서를 바꾸고, 첫 일반 스테이지에 공동 목표와 클리어 판정을 추가한다.

## 해석과 범위

- “매 게임마다 다른 문제”는 **새로 발급된 방마다 다른 무작위 출제 흐름**으로 해석한다. 수학 문제가 유한하므로 서로 다른 방에서 같은 한 문항이 우연히 나올 수는 있지만, 매번 0 + 3으로 시작하는 고정 흐름은 없앤다.
- 이번 스테이지 묶음은 **목표·진행도·완료 판정**이다. 친구가 쓰러지고 구출하는 규칙은 다음 묶음으로 분리한다. 기존의 2~10인 거품 협동은 유지한다.
- 첫 스테이지의 목표 시간은 2분이다. 2분이 지나도 강제 종료하지 않고 경과 시간을 표시한다.
- 학생 개인 문제·오답·정답 수는 영구 저장하지 않는다. 방 전체의 스테이지 설정과 클리어 결과만 기존 체크포인트에 넣는다. 서버 휴면/재시작 뒤 진행 중 개인 정답 수가 초기화될 수 있다.
- `main`과 운영 배포는 건드리지 않고 현재 작업 브랜치에서 검증한다.

## 단계와 성공 기준

1. **무작위 출제**: 방별 난수 시드와 출제 번호를 서버가 관리한다. → 같은 방에서도 연속 문항이 다양하고, 새 방은 고정 첫 문항으로 시작하지 않는다. 선택지 정답은 그대로 서버 전용이다.
2. **스테이지 규칙**: 참가 인원으로 포획·문제 목표를 정하고, 두 목표 충족 시 한 번만 클리어한다. → 1~10인 목표가 증가하며, 제한 시간을 넘어도 실패하지 않는다.
3. **서버 공유 상태**: 시작·진행·클리어를 방의 모든 학생과 교사에게 알린다. → 서버만 목표와 종료를 판정하고, 재접속 시 현재 상태를 받는다.
4. **태블릿/교사 화면**: 작은 목표 표시와 완료 결과를 DOM으로 보여준다. → 터치 조작을 가리지 않고, 교사에게는 팀 집계만 보인다.
5. **검증**: 규칙·통신·화면 테스트, 타입 검사·빌드, 로컬 2인 대표 경로를 확인한다. → 기존 게임의 이동·거품 포획·개인 문제 흐름이 유지된다.

## 제외

- 일반 스테이지 2·3, 보스전, 장기 랭크, 친구 쓰러짐·구출, 전 학년 문제 은행, 학습 기록 영구 저장.

## 확인 결과와 다음 작업

- 계산 규칙 27개, 실시간 서버 31개, 웹 화면 28개 테스트가 통과했다. 관련 타입 검사와 웹·Worker 배포용 빌드도 통과했다.
- 로컬 브라우저에서 새 방 두 개의 첫 문제(`2 + 16`, `8 − 3`)가 달랐고, 두 학생이 같은 맵에서 각자 다른 문제를 받았다. 인원 1→2명에 따라 문제 목표가 2→3개로 늘었다.
- 서버 통합 테스트에서 포획 1회와 정답 2개를 채운 1인 방이 클리어됐다. 자동 브라우저 E2E는 이 PC에 Playwright 브라우저 실행 파일이 없어 실행하지 못했고, 브라우저 수동 경로로 대신 확인했다.
- 목표는 스테이지 시작 시 인원수로 고정한다. 시작 뒤 추가 학생이 입장하면 이번 스테이지 목표와 맵은 늘어나지 않는다. 수업에서는 모두 입장한 뒤 시작해야 한다.
- 다음 묶음은 친구 쓰러짐·구출 규칙이다. 개인 정답 수의 휴면/재시작 복구와 장기 성장 기록은 별도 암호화 설계가 필요하다.

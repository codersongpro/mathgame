# Bubble Semble: 교사 설정 목표와 다음 스테이지

## 짧은 요약

교사가 방을 만들 때 스테이지별 생존 시간과 목표 점수를 입력한다. 서버가 시간·점수를 판정하고, 목표 충족 시 같은 방의 모든 학생을 다음 스테이지로 전환한다.

## 확정된 결정과 기본값

- 교사는 각 스테이지의 클리어 조건을 **시간·점수 모두 충족** 또는 **둘 중 하나 충족**으로 선택한다.
- 수학 문제 정답은 10점, 몬스터 포획은 20점으로 서버에서 계산한다.
- 스테이지 1·2의 설정은 서로 독립적이다. 빈 입력은 기본값으로 처리한다.
- 기본값은 스테이지 1: 120초·100점·모두 충족, 스테이지 2: 150초·150점·모두 충족으로 둔다. 두 스테이지 합계 4분 30초를 10분짜리 4스테이지 세트의 일부로 본 잠정값이다.

## 범위와 전제

- 이번 구현은 스테이지 1에서 2로 넘어가는 흐름까지 만든다. 스테이지 2는 같은 기본 조작·계산 문제를 사용하되 새 몬스터 무리와 별도 시간·점수로 시작한다.
- 교사 목표 시간·점수는 방 발급 시 서버에서 검증·고정한다. 학생이나 브라우저 개발자 도구가 값을 바꾸거나 점수를 제출할 수 없다.
- 기존 포획 수·정답 수는 팀 활동 지표로 유지하되, 교사가 정한 시간·점수가 다음 스테이지 진입 조건을 대체한다.
- 생존 시간은 스테이지의 서버 틱으로 측정한다. 현재는 플레이어 피해/구출 규칙이 없으므로 **시간 버티기**까지만 검증된다. 실제 생존 실패·친구 구출은 다음 묶음이다.
- 개인 학습 내역은 영구 저장하지 않는다. 서버 저장소에는 교사 설정과 팀 스테이지 상태만 남긴다.
- 운영 `main`/Vercel/Cloudflare 배포는 이번 작업에서 변경하지 않는다.

## 작은 단계와 완료 기준

1. **설정 형식·규칙**: 시간/점수 범위를 공유 스키마에서 검증하고 순수 점수·전환 함수를 만든다. → 경계값, 위조 입력, 시간·점수 조합 테스트.
2. **교사 방 생성 화면·API**: 스테이지 1·2 입력값을 교사 인증된 생성 요청으로만 전달한다. → 잘못된 값은 방 생성 전 거절하고, 공개 응답에 교사 비밀키/토큰이 없다.
3. **실시간 서버**: 설정 고정, 정답·포획 서버 점수, 스테이지 전환과 재접속 상태를 구현한다. → 1→2 전환은 한 번만 일어나며 두 학생에게 같은 상태가 전달된다.
4. **학생·교사 화면**: 생존 시간, 목표 점수, 현재 점수와 다음 스테이지를 태블릿에서 읽기 쉽게 표시한다. → 터치 조작·게임판을 가리지 않고 교사 화면은 팀 집계만 보인다.
5. **검증**: 관련 규칙·API·서버·UI 테스트, 타입 검사·빌드, 대표 교사 폼 사용자 경로 테스트. → 기존 방/재접속/10인 게임 동작 유지.

## 제외

- 친구 쓰러짐·구출, 스테이지 3·보스전, 학년별 문제 은행, 장기 성적/랭크, 운영 배포.

## 검증 결과

- 공유 규칙 12개, 게임 코어 28개, 웹 29개, 실시간 서버 33개 테스트 통과.
- 네 패키지 타입 검사와 웹·Worker 빌드 통과.
- 교사 폼에서 목표 점수·클리어 방식을 변경하고 다른 스테이지 입력을 비운 경로를 UI 테스트로 확인.
- 실제 브라우저 수동 플레이와 운영 배포는 이 단계에서 수행하지 않음.

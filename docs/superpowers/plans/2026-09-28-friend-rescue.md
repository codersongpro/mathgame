# Bubble Semble 페이즈 2-5: 친구 쓰러짐과 구출 구현 계획

## 짧은 요약

몬스터에 닿은 학생이 잠시 쓰러지고, 다른 학생이 가까이 가서 태블릿의 `구출` 버튼을 눌러 되살립니다. 서버가 충돌·거리·구출을 판정하고, 모든 학생의 화면에 같은 상태를 보냅니다. 이번 묶음에서는 이 기능만 완성하며 스테이지 3과 보스전은 건드리지 않습니다.

## 무엇을 할지 → 왜 → 어떻게 확인할지

| 단계 | 구현 | 이유 | 완료 기준 |
|---|---|---|---|
| 1. 판정 규칙 | 몬스터 접촉, 쓰러짐, 구출 거리, 부활 보호 시간을 순수 함수로 구현 | 클라이언트가 위치나 구출 결과를 위조하지 못하도록 함 | 접촉·비접촉·거리 초과·자기 구출 불가·보호 시간 테스트 통과 |
| 2. 방 동기화 | 플레이어 상태와 `rescue` 행동을 서버에 추가하고 체크포인트에 저장 | 재접속·두 화면에서 같은 결과를 유지 | 두 학생 WebSocket 테스트에서 쓰러짐·구출·재접속이 일치 |
| 3. 태블릿 화면 | 쓰러진 학생 표시, 안내 문구, `구출` 터치 버튼을 추가 | 키보드 없이 협동할 수 있게 함 | 버튼 활성·비활성 및 상태 안내 테스트, 대표 화면 확인 |

## 이번 묶음의 기본 규칙

- 스테이지가 진행 중일 때만 살아 있는 학생과 자유로운 몬스터의 접촉을 판정합니다. 거품에 갇힌 몬스터는 위험하지 않습니다.
- 접촉하면 학생은 그 자리에서 쓰러지고 이동·거품·문제 제출을 잠시 할 수 없습니다.
- 다른 학생이 80픽셀 이내에서 `구출`을 누르면 즉시 일어납니다. 서버가 학생 ID와 좌표로 판정하며 요청에는 대상 ID나 좌표를 넣지 않습니다.
- 시작 직후와 구출 직후 3초간 재피격을 막습니다. 모든 연결된 학생이 쓰러져 구출자가 없거나 혼자 플레이 중이면 8초 뒤 자동으로 일어납니다. 이 복구는 협동 구출 횟수에 포함하지 않습니다.
- 팀 전원이 쓰러진 시간은 목표 생존 시간에 포함하지 않습니다. 클리어 이후에는 피격·구출을 정지합니다.
- 기존 학생 별명 이외의 개인정보는 새로 저장하지 않습니다. 교사 화면에는 팀 구출 횟수와 현재 쓰러진 인원만 표시합니다.

## 검증과 배포 경계

- 관련 순수 규칙·서버·UI 테스트를 먼저 실행하고, 타입 검사와 필요한 빌드를 수행합니다.
- 실제 브라우저 검증이 가능하면 2인 방에서 접촉→구출→두 화면 반영을 확인합니다. 환경 제약이 있으면 미검증으로 명시합니다.
- `main` 병합과 운영 배포는 별도 승인 단계로 남깁니다.

## 구현·검증 결과 (2026-09-28)

- 서버가 자유로운 몬스터와 학생의 접촉을 판정하고, 쓰러짐·구출·8초 자동 복구·3초 재피격 보호를 처리합니다.
- 구출 요청은 대상 ID·좌표를 받지 않으며, 다른 학생의 현재 위치와 80픽셀 거리만으로 판정합니다.
- 두 학생에게 동일한 구출 상태를 보내고, 교사 화면에는 구출 횟수와 쓰러진 인원만 표시합니다.
- 팀 전원이 쓰러진 틱은 생존 목표 시간에 포함하지 않습니다.
- 순수 규칙 31개, 실시간 서버 34개, 웹 UI 35개 테스트와 세 패키지 타입 검사가 통과했습니다. 웹 프로덕션 빌드와 Worker 드라이런도 통과했습니다.
- 실제 태블릿 브라우저에서 접촉→구출을 수동 검증하지는 못했습니다. 배포 전 Preview에서 2인 실기 확인이 필요합니다.

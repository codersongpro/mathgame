# Bubble Semble 페이즈 3-1: 일반 스테이지 3 구현 계획

## 짧은 요약

기존 1→2 흐름을 1→2→3으로 확장합니다. 세 번째 스테이지에는 독립적인 교사 목표와 더 많은 몬스터를 적용합니다. 팀 수학 관문과 보스전은 다음 묶음으로 분리합니다.

## 이번 묶음의 결정

- 스테이지 3 기본 목표는 **90초·180점·두 조건 모두**입니다. 기존 1단계 120초와 2단계 150초에 더하면 일반전 기본 시간은 6분이고, 이후 4분 보스전을 합쳐 한 세트 10분을 목표로 합니다.
- 교사는 3단계 시간·점수·조건을 비워 두고 기본값으로 시작하거나 직접 설정할 수 있습니다.
- 3단계에는 같은 인원 기준 몬스터를 2마리 더 배치하되, 한 구역 최대 8마리 제한을 지킵니다. 공격·포획 규칙 자체는 유지합니다.
- 3단계 클리어 뒤에는 현재 방에서 결과를 보여주고 대기합니다. 보스전이 구현되기 전까지 자동으로 다음 단계로 넘어가지 않습니다.
- 기존 방의 저장 상태는 `stage3` 값이 없더라도 기본값으로 읽습니다. 새 프로토콜을 운영에 적용할 때는 웹과 Worker를 함께 검증해야 합니다.

## 무엇을 할지 → 왜 → 어떻게 확인할지

| 단계 | 구현 | 이유 | 완료 기준 |
|---|---|---|---|
| 1. 설정·규칙 | 공용 스키마에 3단계 기본값, 게임 규칙에 3단계 몬스터 수 추가 | 학생이 목표와 몬스터 수를 조작하지 못하게 함 | 기본값·범위·최대 8마리 단위 테스트 통과 |

| 3. 교사·학생 화면 | 교사 3단계 설정, 학생 진행·클리어 문구 표시 | 태블릿에서 다음 목적을 분명히 알림 | 설정 폼·결과 화면 테스트와 타입 검사·빌드 통과 |

## 배포 경계

이번 작업은 작업 브랜치에만 저장합니다. 실기 테스트와 `main` 병합·Vercel/Cloudflare 배포는 별도로 확인합니다.

## 구현·검증 결과 (2026-09-28)

- 1→2→3 전환, 스테이지별 새 문제·몬스터·점수 초기화와 3단계 종료 상태를 구현했습니다.
- 기본값은 3단계 90초·180점·두 조건 모두이며, 3단계 몬스터는 인원별 기본 수보다 2마리 많고 최대 8마리입니다.
- 교사 설정·모니터와 학생 진행·결과 안내를 3단계까지 확장했습니다.
- 공용 형식 12개, 게임 규칙 32개, 실시간 서버 35개, 웹 36개 테스트가 통과했습니다. 타입 검사와 웹 빌드·Worker 드라이런도 통과했습니다.
- 실제 태블릿 브라우저에서 1→2→3 전체 흐름은 아직 수동 검증하지 않았습니다. 다음 묶음은 팀 수학 관문입니다.

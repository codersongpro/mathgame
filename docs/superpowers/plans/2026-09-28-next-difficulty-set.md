# Bubble Semble 페이즈 3-4: 보스 클리어 후 다음 난이도 세트

## 짧은 요약

보스를 클리어하면 팀 타임어택 결과를 3초간 보여준 뒤 같은 방에서 다음 세트의 일반 스테이지 1로 이동합니다. 세트 번호와 인원별 팀 기록을 유지합니다.

## 이번 묶음의 결정

- 교사가 지정한 각 스테이지의 **목표 시간과 결합 방식**은 다음 세트에도 그대로 적용합니다. 한 세트 약 10분의 시간 구조를 유지하기 위해서입니다.
- 세트 번호가 1 증가할 때마다 목표 점수는 20%씩 높이고, 몬스터는 최대 8마리 안에서 1마리씩 추가합니다. 보스 체력도 세트마다 25%씩 높입니다. 프로토콜의 범위를 넘지 않도록 점수는 2,000점, 보스 체력은 100으로 제한합니다.
- 문제의 숫자 범위는 이 묶음에서 올리지 않습니다. 학년별 난이도와 1~19단 선택은 별도 콘텐츠 설계가 필요한 다음 페이즈입니다. 이번 난이도 상승은 전투·협동 목표에 한정합니다.
- 보스 기록은 방 안에 `세트 번호·참가 인원·클리어 초`만 최대 24개 저장합니다. 학생별 답이나 실명은 저장하지 않습니다. 공개 개인 순위표는 만들지 않습니다.
- 다음 세트 시작 시 점수·포획·몬스터·거품·관문 상태를 초기화하고, 학생 연결과 같은 방 번호는 유지합니다. 맵 크기는 세트 시작 인원으로 다시 고정합니다.

## 무엇을 할지 → 왜 → 어떻게 확인할지

| 단계 | 구현 | 이유 | 완료 기준 |
|---|---|---|---|
| 1. 난이도 규칙 | 세트 번호별 점수·몬스터·보스 체력 계산 | 시간 구조를 유지하면서 게임 협동 난이도 상승 | 1·2·10세트와 상한 단위 테스트 |
| 2. 서버 루프 | 보스 결과 기록 후 3초 뒤 새 세트 1단계 | 방을 다시 열지 않고 이어서 플레이 | WebSocket 통합 테스트에서 방·학생 ID 유지, 초기화·새 목표 확인 |
| 3. 화면 | 세트 번호·다음 난이도·팀 보스 기록 표시 | 학생·교사가 진행을 알 수 있음 | UI 테스트, 타입 검사·빌드 |

## 배포 경계

작업 브랜치에만 반영합니다. 운영 `main`과 Vercel·Cloudflare는 변경하지 않습니다. 실제 태블릿에서 1세트 전체를 수동 시험한 뒤 운영 배포를 판단합니다.

## 구현·검증 결과

- 보스 클리어 후 3초가 지나면 기존 방과 학생 연결을 유지한 채 다음 세트 1스테이지로 전환합니다.
- 새 세트의 점수·몬스터·보스 체력과 최근 팀 보스 기록을 서버에서 계산·보관하고, 학생·교사 화면에 세트 번호를 표시합니다.
- 게임 코어 39개, 공유 프로토콜 14개, 실시간 서버 37개, 웹 40개 테스트가 통과했습니다. 웹·실시간 타입 검사와 웹 프로덕션 빌드도 통과했습니다.
- 실제 태블릿을 이용한 수동 플레이와 운영 배포는 아직 수행하지 않았습니다.
